# NOOR Codex of Light, Operations Manual

**The one document to read when something is wrong, when something must change, or
when somebody other than you has to run this.**

Everything here is current as of v108. If this file and the code disagree, the code
is right and this file is a bug: fix it in the same commit.

---

## 0. The ninety second version

| | |
|---|---|
| **What it is** | A free Islamic library and school. No ads, no trackers, no account. |
| **Where it lives** | `noorcodex.com` and `noorcodex.ca` |
| **Repo** | `github.com/Eouchi147/noor`, branch `noor-v2-illuminated` |
| **Host** | Vercel. Static files plus 27 serverless routes under `/api`. |
| **Database** | Redis, via `REDIS_URL` or Upstash/Vercel KV REST. Everything dynamic. |
| **AI** | OpenRouter, free models only, never billed unless deliberately allowed. |
| **Money** | Stripe. Gifts only. No subscriptions sold, no paywall, ever. |
| **Owner console** | `noorcodex.com/admin`, one password, not linked from anywhere. |
| **How a change ships** | You drag a zip into GitHub's web UI. Vercel deploys in ~1 min. |

**The single most important operational fact:** the site is designed so that
**every dynamic thing degrades to a written fallback**. If Redis is gone, if the AI
is dark, if Stripe is unreachable, the library still reads correctly. This is why an
outage can stay invisible for weeks, and why the health strip at the top of `/admin`
exists.

## 1. What runs where

```
  reader ──► Vercel edge
              ├── static HTML, one file per room, generated by scripts/gen-*.py
              ├── /assets/*         shared css and js, cached one year, versioned by ?v=
              ├── /study/<n>.json   the Qur'an study companion, one file per surah
              ├── /verse/<n>.json   the verse-by-verse layer, one file per surah
              ├── /node/<id>.json   one file per node of the Path
              └── /api/*            27 serverless functions (Node, ESM)
                                      ├── Redis  (journal, counters, settings, cache)
                                      ├── OpenRouter  (the Lantern)
                                      └── Stripe  (gifts, the ledger)
```

**There is no build step on Vercel.** The HTML in the repo is what is served. The
Python generators run *on your machine* (or in a Claude session) and their output is
committed. This is deliberate: it means a broken generator can never take the site
down, and the site can be understood by reading the files it serves.

## 2. Environment variables

Set in **Vercel → project → Settings → Environment Variables**. After changing any
of them you must **redeploy** (Deployments → ⋯ → Redeploy) for the change to take.

### Required for the console to open at all

| Variable | What it is | Get it from | Without it |
|---|---|---|---|
| `ADMIN_PASSWORD` | The one password for `/admin`. Make it long. | You choose | Console cannot be unlocked |
| `ADMIN_SECRET` | 40+ random characters. Signs the session cookie and authorises writes. | You generate | Console returns "admin not configured" |

### Required for the Lantern (the AI)

| Variable | What it is | Get it from | Without it |
|---|---|---|---|
| `OPENROUTER_API_KEY` | Starts `sk-or-`. | openrouter.ai/keys | Every AI feature falls back to written text. Site still fine. |
| `OPENROUTER_MODEL` | *Optional.* Force one model. **Ignored if it is not free.** | none | The house picks the best free model itself. This is the recommended state. |
| `ALLOW_PAID_MODELS` | Set to `1` **only** if you intend to be billed. | none | Paid models are dropped before the request is made. Leave unset. |

### Required for the store (strongly recommended)

Either pair works; the code speaks both.

| Variable | What it is |
|---|---|
| `REDIS_URL` | Any ordinary Redis URL, `redis://` or `rediss://`. Spoken over the native protocol, no npm package. |
| `KV_REST_API_URL` + `KV_REST_API_TOKEN` | Upstash / Vercel KV REST. Also accepted: `UPSTASH_REDIS_REST_URL` / `_TOKEN`, `KV_URL`, `REDIS_TLS_URL`. |

**Without a store:** the journal cannot accept replies, visitor counts do not
accumulate, the settings dials do not persist, and the free-model list is re-fetched
on every cold start. The library itself is unaffected.

### Money

| Variable | What it is |
|---|---|
| `STRIPE_SECRET_KEY` | Starts `sk_live_`. Reads charges for the ledger and takes gifts. |
| `NOOR_MONEY_MODE` | `donate` (default) or `guardian`. |

### Tuning, all optional

| Variable | Default | What it does |
|---|---|---|
| `LANTERN_FREE_PER_DAY` | built-in | How many AI answers an anonymous reader gets per day |
| `LANTERN_KEYED_PER_DAY` | built-in | Same, for a reader holding a Lantern key |
| `LANTERN_KEYS` | none | Comma separated keys that raise a reader's allowance |
| `LANTERN_SALT`, `NOOR_RATE_SALT` | none | Salts for the rate-limit fingerprints. **Set these.** Without them the fingerprint is weaker. |
| `ASK_PUBLIC`, `GUIDE_PUBLIC` | none | Open the ask and guide endpoints to the public |
| `ANTHROPIC_API_KEY` | none | Unused on the current path. Safe to leave unset. |

## 3. The Lantern, how the AI actually chooses a model

This is the part that broke, so it is documented in full.

### The rule about money

**Nothing bills unless you deliberately turn billing on.** Anything not on
OpenRouter's own free list is dropped *before* the request is made, including
whatever `OPENROUTER_MODEL` is set to, unless `ALLOW_PAID_MODELS=1`.

### The three layers, in order

1. **The store.** `nlm:free` holds the list of free models as last seen, with a
   timestamp. Any instance, however cold, reads it in one round trip.
2. **OpenRouter's live list.** Fetched when the store's copy is older than six hours
   or missing. Filtered to free and text-capable, ranked, and written back to the store.
3. **`FREE_CHAIN` in `api/_models.js`.** A written guess, reached only when the store
   and the network have *both* failed. If you see these names in a log, two layers
   are down.

On top of all three: `nlm:good` remembers the last model that actually produced
words, and it is asked first.

### Why it broke, so it is never rebuilt this way

`modelChain()` is synchronous. It reads an in-process variable filled by an awaited
fetch. **On Vercel every cold start begins with that variable empty**, so it returned
the written fallback. Five endpoints called it that way. A cold start is not the rare
case; it is most invocations. So most of the time, most of the Lantern was asking
retired model names, waiting nine seconds each, and returning nothing.

**Rule: never call `modelChain()` on a request path. Always `await liveChain()`.**
`tests/api-audit.mjs` fails the build if anything does.

### The nightly refresh

`/api/warm` runs at **04:00 UTC daily** (`vercel.json` → crons). It:
1. forces a fresh free-model list into the store,
2. generates the day's light and stores it,
3. runs a one-word probe and records the result at `nwarm:last`,
4. on the 1st of the month, runs the journal triage.

The health strip reads `nwarm:last`. **If "Nightly" says more than 36h, the cron is
not running.**

## 6. The build system

All generators are Python 3, run from the repo root, and write directly into the repo.

```
python3 scripts/gen-verse-notes.py     # /verse/index.json + /verse/<n>.json
python3 scripts/gen-quran-study.py     # /study/<n>.json  + build/quran-study.js
python3 scripts/gen-three-lives.py     # three-lives.html
python3 scripts/gen-good-life.py       # good-life.html
python3 scripts/gen-<room>.py          # one room each
node    scripts/build.mjs              # nodes.js, nodes-index.js, node/<id>.json
```

`scripts/room.py` is the shared page shell (head, nav, hero, footer, motion layer).
`scripts/nav49.py` is the menu, and it is **baked into each page at generation time**,
so changing the menu means regenerating or re-injecting across every page.
`scripts/synergy.py` emits the "Where to go from here" band **with its own stylesheet**
,  never hand-write that markup, it will render unstyled.

### ⚠ Hazard list, read before running any generator

- **`scripts/gen-heroes.py` is far BEHIND `heroes.html`.** The shipped page has the
  motion loader, the current stylesheets and the RTL layer; the generator does not.
  Running it **reverts all of that**. Fix the generator first or patch the page.
  (Its syntax error is fixed, so it *will* run now. That is exactly the danger.)
- Assume the same risk for any generator whose page has been hand-patched since.
  Diff before you commit: `cp page.html /tmp/before && python3 scripts/gen-page.py && diff`.

## 7. The guards, run these before shipping anything

```bash
python3 scripts/gen-verse-notes.py    # refuses to write if any verse note is malformed
node scripts/check-admin.mjs          # console structure: every pane reachable
node tests/lantern.mjs                # 25 · the model chain, no network needed
node tests/api-audit.mjs              # 87 · every route: auth, caching, secrets, cold start
node tests/symbols.mjs                # no symbol of another faith is drawn anywhere
node tests/dials.mjs                  # the console's switches actually switch    (server :8433)
node tests/figures.mjs                # every drawing on every page, 3 widths     (server :8433)
node tests/mushaf.mjs                 # 42 · the Qur'an player and verse layer  (server :8433)
node tests/e2e.mjs                    # 121 · the whole site                    (server :8123)
```

Two local servers, because two suites were written against different ports:

```bash
python3 /tmp/vercelish.py    # :8433, mimics Vercel's clean URLs
# and a plain static server on :8123 for e2e
```

**What each guard exists because of:**
- `check-admin.mjs`, one missing `</div>` once blanked the entire console.
- `lantern.mjs`, the cold-start fault above.
- `api-audit.mjs`, nine routes shipped with no `Cache-Control` at all.
- `figures.mjs`, 700 problems, including a gradient that had never once painted.
- `symbols.mjs` , a Christian cross was drawn as a grave marker on an Islamic site.
- `dials.mjs` , the journal was switched off in the console and kept working.

## 8. Runbooks

### The Lantern is dark

1. Open `/admin` → the health strip. What does the **Lantern** chip say?
2. `no key` → `OPENROUTER_API_KEY` is not set in Vercel. Set it, **redeploy**.
3. `dark` → open the **Lantern** pane and press probe. It runs one real request and
   tells you which of four things is wrong, in one sentence:
   - **key**, OpenRouter refused the key. Check it still exists at openrouter.ai/keys.
   - **policy**. *This is the most common one.* The key works but no provider will answer.
     Free models are served by providers that may train on prompts, so OpenRouter
     hides them until you allow it: **openrouter.ai/settings/privacy → enable the
     free-model / prompt-training option.** No redeploy needed.
   - **limit**, every model rate-limited. Free models share a small daily allowance.
     It resets daily. A few dollars of credit on OpenRouter raises it permanently
     **without making any request paid**.
   - **unknown**, read the per-model table underneath; it holds the exact words each
     one returned.
4. The site is not down. Every AI surface has a written fallback.

### "Nightly" says never, or more than 36h

The cron is not firing. Check **Vercel → project → Cron Jobs**. `vercel.json` declares
`/api/warm` at `0 4 * * *`. On some plans crons must be enabled per project. You can
always run it by hand: visit `https://noorcodex.com/api/warm`.

### Store says none

`REDIS_URL` or the KV pair is not set, or is wrong. Until it is fixed: the journal
cannot take replies, counters do not accumulate, and dials do not persist. Nothing
else breaks.

### A dial in the console does not seem to do anything

Dials come in two kinds and they fail differently.

**Server-side dials** (`journal.replies`, `lantern.on`, the rate limits) are read by
the API on every request and take effect immediately.

**Reader-facing dials** (`journal.on`, `notice.text`) have to reach a *static* page.
The menu is baked into every page at generation time, so no server dial can reach it.
`assets/noor-dials.js` reads `/api/settings` on every page and applies them.

If a reader-facing dial appears to do nothing, check in this order:
1. Is the page carrying `assets/noor-dials.js`? Every page except `/admin` should.
2. Does `GET /api/settings` return the dial in its `s` object? Only dials marked
   `pub: true` in `api/settings.js` are sent to the public site.
3. The script **fails open by design**: if the request does not land, the site behaves
   exactly as built. A library that hides itself over a network hiccup is worse than
   one that shows a section an hour longer than intended. Verified in `tests/dials.mjs`.

### A reply got onto the journal that should not have

Nothing appears on the journal until you approve it in **Journal → replies waiting**.
If something is live: open the same pane, find it, remove it. The public promise is
that *no reply is ever refused for disagreeing*, refuse only spam, scams, coarse
language a child should not meet, anything unlawful, anything publishing a private
person's details, and anything written to harass someone by name.

### The site is showing an old version

Vercel deploys on push. Check **Deployments** for a failed build. Then check the
service worker: `sw.js` caches aggressively and its version constant (`var V =
"noor-vNN"`) must be bumped whenever a cached asset changes, or returning readers
keep the old copy.

### Money questions

- The public page names **only the 2.5% zakat**, plus one honest line that the rest
  supports the person building it.
- The private waterfall lives in **Giving → the ledger**: zakat is taken **on gross,
  first, always**; then system upkeep; then the household floor; then the remainder.
  In a thin month the floor goes unmet **and the zakat is still owed**. That is
  deliberate and it is tested.
- Nothing writes to Stripe from the console. Reading only.

## 9. How a change reaches the live site

1. Changes are made and tested (see §7).
2. They are packaged as one or more zips.
3. You open the repo on GitHub → **Add file → Upload files**.
4. **Unzip first, then drag everything at the top level in one go**, loose files and
   folders together, without opening the folders. GitHub preserves the paths.
   Dragging a folder **adds and replaces only the files inside it**; it never deletes
   the rest of that folder.
5. Commit. Vercel builds and deploys in about a minute.
6. GitHub's web uploader takes at most ~100 files per drag, which is why large
   deliveries arrive as several numbered zips.

**Deletions cannot be done by drag-and-drop.** To delete a file, open it on GitHub and
use the ⋯ → Delete file.

## 10. Content standards, in one place

These are not style preferences. They are the reason the library can be trusted.

- **Every teaching claim carries an evidence badge**: `quran` (the text states it),
  `sunnah` (an authentic report establishes it), `debated` (scholars, readings or
  gradings differ, and we say so), `editorial` (our own reading, offered as a reading).
- **A `sunnah` or `debated` badge without a named source is a build failure**, not a
  style problem. The verse-notes generator refuses to write.
- **Never invent** a hadith, a chain, a grading, a number, or an occasion of revelation.
  If a report is believed to exist but its number is uncertain, make the point *without*
  a number and badge it as a reading. A wrong hadith number is worse than no note.
- **No em dashes or en dashes anywhere.** Guarded in e2e.
- Write **the Prophet ﷺ** with the symbol, and **Qur'an** with the apostrophe.
- Illuminated manuscript art only. **No faces of prophets or companions.**
- **No symbol of another faith is ever drawn, anywhere.** This is not a matter of
  words: a cross once reached a published page as two line commands in an SVG path,
  with the word "cross" appearing nowhere, so no text search could have found it.
  `tests/symbols.mjs` parses every path into its straight segments and reports a
  horizontal stroke crossing a vertical one at an interior point of both. Plus-shapes
  that are genuinely a lattice, a window or a kite's spars are cleared **by name** in
  that file with their reason, so a new one can never hide among them.
- Relief and medicine use the **crescent**, never the medical cross.
- **The still frame of every animated figure must already be true.** Motion is the
  second telling, never the only one. A reader with reduced motion loses the motion
  and nothing else.
- The journal is **not** the teaching voice. It badges nothing because it teaches
  nothing, it never issues a ruling, and it exists to be corrected.

## 11. Security posture

- One password, one secret, both in Vercel only. **No key is ever in the repo** , 
  `tests/api-audit.mjs` scans every file for literal secrets on every run.
- The console is `noindex` and linked from nowhere.
- Every admin route verifies a signed cookie against `ADMIN_SECRET` and sets
  `Cache-Control: no-store`.
- No trackers, no third-party analytics, no fonts that phone home except Google Fonts.
- Rate limiting is by salted fingerprint. **Set `LANTERN_SALT` and `NOOR_RATE_SALT`.**
- Reader emails exist in exactly one place, journal replies, so you can answer, and
  are stripped from every public surface.

## 12. If somebody else has to take this over

Read, in this order: this file, then `NOOR-HANDOFF.md` (the change log, newest last),
then `api/_models.js`, which is the most instructive file in the repo because it
documents its own outage, then `scripts/room.py`.

The project's standard is written down in one line in `assets/anim.css` and it governs
everything else: **motion is evidence, not decoration, and the still frame must be the
honest one.**
